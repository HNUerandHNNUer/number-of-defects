# Fortran Brownian dynamics OpenMP 完整源码

这份程序由本目录上一级的 `bd_read.f90`、`module.f90` 优化而来。原文件没有修改。
使用单台机器的多核 CPU（OpenMP），不是 GPU 或跨节点 MPI 程序。

## 文件

- `module.f90`：完整模块、原随机数程序、并行工作缓冲区。
- `bd_read.f90`：完整主程序、读入、力计算、积分、邻居列表和输出。
- `initial.xyz`：随包提供的原始 3000 粒子初始构型副本。
- `Makefile`、`run_parallel.sh`：Linux 编译和运行入口。
- `validate.py`：Python 标准库实现的编译、串并行一致性与短程计时工具。
- `reference_original/`：原始两份源码，供验证脚本对照。
- `validation_results.json`：本机 10000 步验证结果。
- `source_hashes.json`：优化前输入文件的 SHA-256。

无需运行生成器，编译两份 f90 文件即可。`build_sources.py` 仅是本地开发时的生成记录，不是运行依赖。

## Linux / HPC 编译运行

```bash
gfortran -O3 -fopenmp -ffp-contract=off module.f90 bd_read.f90 -o bd_parallel
export OMP_NUM_THREADS=4
export OMP_DYNAMIC=FALSE
export OMP_PROC_BIND=close
export OMP_PLACES=cores
./bd_parallel > run.log 2>&1
```

也可运行 `make`，然后 `bash run_parallel.sh > run.log 2>&1`。
在作业调度器中申请 1 个进程、4 个 CPU 核；线程数不应超过所申请核数。
不要用 `mpirun -np 4` 启动本程序：这会启动四个独立模拟并争抢相同输出文件。
对现有 3000 粒子系统建议先测试 2、4 线程；更多线程未必更快。
不要使用 `-Ofast` 或 `-ffast-math` 来做严格数值一致性对照。

默认仍为 Fext=25、dt=0.01、gamma=1000、T=1、100 条链，每条 30 粒子，
生产段 1000000000 步，每 100000 步保存一次。运行目录需要 `initial.xyz`。
每次独立运行使用独立目录，避免覆盖已有 out-*.xyz。

短测示例（环境变量只覆盖步数、输出间隔和种子）：

```bash
BD_STEPS=10000 BD_SAVE=10000 BD_SEED=123456 OMP_NUM_THREADS=4 ./bd_parallel > short.log 2>&1
```

不设置 BD_SEED 时仍按原程序使用系统时钟生成随机种子。
同一种子跨编译器/运行库不保证相同随机序列。

## 优化与保持的行为

1. FENE 键和角力按链分配给线程。同一链内仍按原顺序累加，没有跨链共享粒子的写冲突。
2. 邻居对的相互作用并行计算，每个相互作用仅有一个线程写入缓冲区。
3. 在每次邻居更新后建立按原全局邻居表顺序排列的粒子关联表。每个粒子由单个线程
   收集相互作用，保留原加减顺序；噪声、活性和壁力插入点也与原版一致。
4. 随机数仍按粒子编号串行产生，每粒子三个标量 uniform 抽样。工作线程不调用随机数发生器。
5. virial 保留原顺序串行求和，不使用无固定顺序的并行 reduction。
6. 缓冲区复用；关联表仅在原程序本来需要更新邻居表时重建。

FENE/WCA/角力/活性力/球壳公式、力参数、链端推进规则、角度条件
`-0.99 < p < 0.99`、最小镜像处理、邻居更新判据、每步统计方式均保留。
尤其保留原来的 `deltar=dt*vel; pos=pos+deltar; vel=acc/gamma; Compute_Forces` 时序。
没有加入位移钳制、FENE 分母截断、投影到球面或额外平衡阶段。

原程序对每对粒子的全局加法顺序可按不同原子独立重放，因为这些加法不读取其他原子的 acc。
这允许并行收集，同时避免 atomic 的竞争和线程调度造成的求和顺序变化。

## 非动力学修正

- 原读取构型版本未赋值 density 却将其用于压力。本版将其设为 N/volume，
  只影响该三维压力诊断；它不是球面面积占据率 phi，也没有改动力计算。
- initial.xyz 检查 N=nchain*mchain、正盒长、类型 1 和 BoxSize 标头。
- 邻居表容量不足时直接停止，避免原版继续越界写内存。
- XYZ 标头步数改为 I10，避免十亿步时原 I9 输出星号；文件名仍为 10 位步数。
- 释放新增缓冲区及 Head；移除遗留的乱码和被注释掉的旧初始化代码。

## 实际验证

Windows 本机，GNU Fortran 16.2.0，优化选项 `-O3 -ffp-contract=off`，
并行版另加 `-fopenmp`。使用随包的 3000 粒子构型，Fext=25、种子 123456。

2000 步和 10000 步两个短测均完成。10000 步结果：

| 程序 | 耗时（秒） | 相对原串行速度 | 最后保存帧与原版坐标最大差 |
|---|---:|---:|---:|
| 原串行 | 5.205 | 1.00 | — |
| 优化版 1 线程 | 6.846 | 0.76 | 0 |
| 优化版 2 线程 | 4.777 | 1.09 | 0 |
| 优化版 4 线程 | 3.742 | 1.39 | 0 |

原串行与 1/2/4 线程版本的末帧 XYZ 文件 SHA-256 完全相同；10000 步热力学输出也相同。
这是该编译环境下保存精度的一致性证据，不是跨编译器或任意长轨迹逐位一致的承诺。
原串行测试版本只做了固定随机种子、缩短步数、末帧输出和相同的压力/标头修正，
未修改其力计算与积分循环。

另以 `-O0 -g -fopenmp -fcheck=all -fbacktrace -ffpe-trap=invalid,zero,overflow`
运行 4 线程 10000 步，通过数组检查和浮点异常检查。调试版不同优化级别的末帧
不要求与 O3 版本逐位相同。

计时是每配置一次本机短测，包含进程启动和构型读写；不是完整性能统计或 HPC 加速保证。
本机 OpenMP 运行库提示不支持 CPU affinity，线程并行仍正常完成；目标 Linux 机器需重新计时。
单线程缓冲开销会使优化版变慢。邻居表、随机数及部分统计仍串行，限制了加速上限。

复现：

```bash
python validate.py --compiler gfortran --steps 10000 --threads 1,2,4
```

验证产物只写到 validation 子目录，不执行默认十亿步生产模拟。

## 物理正确性的边界

本次验证针对“并行版是否忠实复现原程序”，不证明原算法和高活性参数已经数值收敛。
原有延迟使用力的积分方式、FENE 越界没有保护、角力截断、BD 温度/压力的解释等问题仍在。
这次并行化不会修复此前讨论的高活性过长键问题；也不能用运行成功替代步长收敛验证。
